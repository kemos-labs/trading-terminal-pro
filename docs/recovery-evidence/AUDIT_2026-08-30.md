## Blocking findings

1. **Canonical contracts are absent.** There are no `/api/v1` endpoints, no shared JSON Schema package, no runtime validation of serialized REST/MCP output, and no documented legacy adapters.
2. **The target service architecture is absent.** Fastify and MCP remain JavaScript and the Python worker remains `macrovol-api`, not isolated as `services/rates-worker`.
3. **OpenAPI is incomplete.** It describes 19 operations while runtime discovery finds roughly 50 application API routes. Passing the existing validator proves only that the incomplete document is internally shaped as expected.
4. **MCP is not contract-complete.** Its tools lack strict result schemas and mostly proxy REST payloads instead of exposing validated analytical capabilities.
5. **Route parity is not runtime parity.** The prior script compares frontend literals to a hand-maintained route manifest, so newly registered or missing runtime routes can evade the gate.
6. **The workflow authority is duplicated and broken.** `scripts/generate-workflow-registry.mjs` fails with `ReferenceError: spreadCount is not defined`; navigation, registry, OpenAPI, MCP, and tests are not generated from one source.
7. **The E2E gates are mislabeled.** `test:e2e:real-server` and `test:visual` run the same browser-mocked suite. Browser interception supplies most success data, so this is not the required real-server success path.
8. **Visual/accessibility coverage is not honest.** Crypto E2E disables Axe color-contrast checks, screenshots are not compared against baselines, and required workflows can be empty while tests pass.
9. **Provider requirements are incomplete.** There is no Velo credential/entitlement branch. Some UI paths and retained screenshots depend on live public upstreams rather than deterministic adapter fixtures.
10. **Required analytics are missing or wrong.** SERFF does not implement the exact required four-leg spread/ratio; the Rates screenshot has a one-row strip; Greek units/exposure scope need correction; and the lazy 3D Greeks surface is explicitly absent.
11. **Crypto semantics fail visual inspection.** Retained screenshots show negative DTE expired options marked `Observed`, a flow call counted as a put/`other` expiry, zero-computable positioning, absent basis/history, and an empty Trade & Risk workflow. A persistent unrelated equity-chain failure toast overlays every Crypto view.
12. **The product shell is fragmented.** Crypto is a separate mini-application rather than the unified terminal shell. Home screenshots show loading or oversized launcher regions and expose internal IDs in user-facing copy; mobile navigation is clipped with undersized targets.
13. **Evidence is not reproducible.** The former report cites temporary `/tmp` screenshots, claims owner preservation that is no longer true, calls architectural assumptions measured performance, claims warning-free gates despite React/Recharts warnings, and reports a clean worktree while also listing an uncommitted file.
14. **Independent final reviews are missing.** The retained visual review covers only selected images, no independent security/API or math/provenance approval is recorded, and the current Orca independent-agent runtime fails to launch (`orca-ide: bad option: --no-sandbox`). This cannot be waived under the master prompt.
